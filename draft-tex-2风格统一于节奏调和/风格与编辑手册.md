《人工智能的数学思维》书稿风格与编辑手册（完整版）
本手册用于指导本书的写作、润色与后续大模型协作（Claude / glm 等）。所有参与人员——包括作者、助教与大模型——都应以此为共同参照。

1. 读者对象与写作目标
1.1 读者对象
* 年级与专业背景
    * 各个专业的本科生与研究生；
    * 有一定实践经验的程序员；
    * 读者可能来自计算机、软件工程、数学，也可能来自社会学、教育学、人文社科等跨专业背景。
* 数学基础情况
    * 默认读者上过大学阶段的基础数学课（高等数学、线性代数、概率论等），大致相当于“中等水平”；
    * 可以已经忘了很多细节，对公式推导不再熟练；
    * 对于社会学 / 文科等跨专业学生，希望他们可以把自己视作“曾经学过一点数学、但有些生疏的读者”。
* 本书原则：遇到关键数学概念，要尽量重新建立直观理解，而不是假设读者已经完全掌握。
* 编程 / AI 基础情况
    * 无硬性要求；
    * 读者可以完全没有 Python、机器学习背景；
    * 也可以是已有开发经验、希望从“数学思维角度”重新理解 AI 的工程师。
1.2 写作目标与整体定位
* 本书风格定位为：融合通识教育 + 课堂讲解体。
* 整体调性接近《数学之美》《贝叶斯的博弈：数学、思维与人工智能》一类通识读物：
    * 一方面保持通俗易懂与阅读友好；
    * 另一方面兼顾计算机与软件工程专业学生所需的专业深度。
目标不是“列一堆知识点”，而是帮助读者在阅读中逐渐建立对：数学思维 → 算法思维 → 工程思维  三者之间关系的整体把握与信心。

2. 整体风格与语气基准
2.1 文本形态：像一堂有温度的深度课
* 文本整体应当像一堂结构清晰、语气自然、行文有温度的深度课。
* 理想读者体验：仿佛坐在教室里，跟着一位耐心的老师板书、推导、举例，而不是在读技术报告或论文。
2.2 语气基准与风格边界
* 语气更偏“课堂讲解体”：
    * 通过提问、铺陈和小结，引导读者一步步思考；
    * 强调推理过程，而不是只给结论。
* 语气基准：温和、理性、启发式、具有思维引导。
* 避免两种极端：
    1. 典型“工科范”：
        * 过于凝练，极度压缩信息密度；
        * 关键推理步骤省略不写；
        * 让读者觉得“我是不是早就该懂，只是我太笨”。
    2. “哲学散文范”：
        * 大段抽象议论；
        * 缺乏具体的数学、算法或工程落地；
        * 读完难以知道“能算什么”“能用什么”。
* 目标：在可理解的细节与适度留白之间取得平衡：
    * 该讲清楚的地方讲透；
    * 不因炫技而堆砌复杂符号或证明。
2.3 具体语言习惯
* 尽量减少被动语态，优先使用自然的口语化书面表达。
* 可以适度使用引导性短语，例如：
    * “我们可以看到……”
    * “换句话说……”
    * “接下来，我们尝试从另一个角度理解……”
* 但不要滥用这些词，让它们自然嵌入，避免“每句都以‘我们’开头”。
* 禁用 / 严格限制：
    * 空洞口号（如“人工智能正在改变世界”“站在时代的风口上”这类不带信息的句子）；
    * 带有居高临下色彩的词，例如：
        * “显然”“不难发现”“一眼就能看出”等，
        * 除非处于严格数学语境，且前文已充分铺垫。
2.4 读者感受目标
* 不恐吓、不贩卖焦虑。
* 让读者在阅读过程中感到被理解、被陪伴：
    * 可以坦然接受“这个地方我以前没弄懂”；
    * 可以在安全、舒展的语气中重新建立对数学与 AI 的信心。
理想状态是：
读者不是被动接收知识，而是在作者温和而清晰的引导下，一步步“跟着思考”。

3. 当前问题与结构修复方向
3.1 目前存在的主要问题
现有书稿中主要问题包括：
1. 章节与小节过碎、过散
    * 同一主题被拆成过多细小片段，导致阅读节奏被打断；
    * 小节之间缺乏自然衔接，读者难以构建整体地图。
2. 过于凝练，缺乏过渡与思维引导
    * 信息密度高、跳步明显，中间推理环节省略；
    * 新概念、新符号时常缺少引入动机与背景。
3. 术语不统一
    * 同一概念在不同章节使用不同翻译或表述；
    * 中英文混用随意，读者不易形成稳定记忆。
3.2 修复原则
后续所有章节重写 / 润色 / 扩写，应优先围绕以上三点进行修复：
* 合并过碎的小节，压实结构层级；
* 补出关键过渡与思维引导句；
* 统一术语与中英对应关系。

4. 段落与小节的写作规则
4.1 段落长度与节奏
* 每个段落建议控制在 ≤ 7 行（按当前版式），避免“整屏一大坨文字”。
* 如一段内部逻辑复杂，应主动拆成 2–3 个自然段。
* 段与段之间要有“气息起伏”：
    * 有的段负责铺垫，有的段负责给出关键洞见，有的段负责小结与过渡；
    * 避免多个段落内容功能完全雷同。
4.2 段内内容与思维引导
* 删除机械重复：
    * 对同一观点，不要用几乎相同的句子连续重复；
    * 如需强调，可通过换角度、举新例子来加深印象。
* 添加必要的过渡句 / 思维引导句：
    * 例如：
        * “为什么这样说？关键在于……”
        * “如果从概率的角度看，这个结论就更自然了。”
    * 用于连接前后概念，减少逻辑“断层”。
* 思维引导句要适度：
    * 不要每句话都加“我们来看一下”；
    * 让引导句像课堂上的“轻轻点一下”，而不是密集地敲黑板。
4.3 推荐的小节内部结构（subsection）
一个常规 \subsection 内部，可以遵循如下结构（可灵活调整）：
1. 引入
    * 提出一个问题、现象或小故事；
    * 用 1–3 句话说明“这一节要解决什么”。
2. 概念 / 原理解释
    * 给出核心概念或定理；
    * 用直观语言解释其含义和适用条件。
3. 例子 / 类比 / 图示
    * 用具体例子、可视化或类比帮助读者建立直觉；
    * 尽量与后续章节或实战场景呼应（如推荐系统、图像识别等）。
4. 小结 / 过渡
    * 回顾本节的关键点；
    * 简单点明它在整章 / 全书中的位置；
    * 为下一节留下钩子，例如：“接下来，我们会把这个想法推到高维空间。”

5. 图表与例子的使用原则
图表与例子是帮助理解的工具，而不是装饰品。
* 每个图表都应回答一个明确问题，例如：
    * “这张图可视化了哪两个变量的关系？”
    * “这个示意图对应公式中的哪一步？”
* 在正文中引用图表时，至少要说明：
    * 该看哪里（哪个轴、哪个区域）；
    * 看出来什么（例如趋势、对比、极端情况）。
* 例子选择原则：
    * 尽量贴近日常经验或应用场景（如投票、推荐、分类、搜索、路径规划等）；
    * 一个概念可以有“直观小例子 + 稍微工程一点的例子”两级结构。
* 避免为“凑趣味”而加入与主题关联较弱的例子，以免分散注意力。

6. 术语与中英混用规范
6.1 术语统一
* 为每个重要术语确定唯一的标准中文表述，并在首次出现时给出英文：
    * 例如：
        * 前缀码（prefix code）
        * 监督学习（supervised learning）
        * 损失函数（loss function）
* 禁止同一概念使用多个中文翻译混用：
    * 如“前缀码 / 前缀编码 / 前缀式编码”只能保留一个。
6.2 中英混用原则
* 正文中：以中文为主，第一次出现时在括号内标出英文。
* 涉及代码、API 名称、公式变量时，可直接使用英文，并在第一次出现时简要解释。
6.3 术语表建议
* 建议维护 docs/Terminology.md（术语表），包含：
    * 中文术语
    * 英文术语
    * 本书中的典型用法或所在章节
* 所有参与润色与扩写的大模型与助教，在不确定用词时，优先查阅术语表，以避免“越改越乱”。

7. 面向大模型的技术规范（Claude / glm 必看）
本节为硬性约束，专门用于指导大模型在 VSCode + LaTeX 环境下安全协作。
7.1 分批处理长文件
* 若文件内容较长，必须分批处理：
    * 推荐每次只处理一个 \section 或一个 \subsection；
    * 以小节为单位便于逐节校对、回滚与版本管理。
7.2 保持 LaTeX 结构与命令不变
* 严禁随意改动：
    * 章节命令：\chapter、\section、\subsection 等；
    * 标签与引用：\label{...}、\ref{...}；
    * 数学与环境结构：\begin{definition}、\begin{figure}、\begin{equation} 等。
* 除非有明确指令，不新增、不删除整个环境，只在环境内部修改文字内容。
7.3 缩进与空行格式
* 尽量保留原有缩进与空行，做到：
    * 同一逻辑块的换行位置基本不变；
    * 不主动把所有内容“揉成一行”或“全打散”。
* 目的是：
    * 在 VSCode 中进行行级 diff 时更清晰；
    * 方便人工检查和直接替换。
7.4 输出形式与 diff 视图
* 用于写回书稿时，输出应为：
    * 完整、可直接复制的 LaTeX 文件片段；
    * 结构、标签、环境命令保持不变。
* 用于审稿与确认修改时，推荐使用“三段式输出格式”：
    1. %% 原文...（原始 LaTeX 内容）...
    2. %% diff- ... 原句 ...
        + ... 修改后句子 ...
        * - 行表示删除 / 被替换的原内容；
        * + 行表示新增 / 修改后的内容。

    3. %% 修改后...（可直接写回文件的最终版本）...

8. 作者 / 模型自检清单
在写作或润色完一段内容后，可以用下列问题做快速自检（人类和大模型都适用）：
1. 读者能看懂吗？
    * 假设读者是社会学或文科专业，只在大一上过高数：
        * 他能在不查教材的情况下大致理解这一段吗？
        * 如果不能，是否需要多一段直观解释或例子？
2. 结构是否过碎或过散？
    * 同一主题是否被拆成过多细小段落或小节？
    * 是否缺少从上一节自然过渡到这一节的引导句？
3. 这一段是否“憋得太紧”？
    * 段落是否超过 7 行？
    * 是否把多个推理步骤挤在一大段中，没有适当换行？
4. 语气是否友好、不居高临下？
    * 是否出现“显然”“不难发现”等可能压迫读者的字眼？
    * 是否有空洞口号或与内容无关的煽情语句？
5. 术语是否统一？
    * 是否引入了与术语表不一致的新译名？
    * 是否在同一章节中混用了多个中文表达指同一英文术语？
6. 是否呼应本书主线？
    * 是否至少用一句话点出：
        * 这一节的内容与“数学思维 / 算法思维 / 工程思维”的关系？
        * 它在整章或整本书中的位置？
